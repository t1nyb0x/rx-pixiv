# ADR 0008: キャッシュはインメモリ TTL+LRU とし Redis を導入しない

- Status: Accepted
- Date: 2026-08-10
- Issue: -

## Context

rx-twitter は Redis を持つ。ただしその理由は**キャッシュではない**。
別プロセスである Astro ダッシュボードがギルド設定の source of truth を持ち、
Bot とその設定を共有する必要があるためである。
その結果 rx-twitter は、三値 `ConfigResult{found|not_found|error}`、
`REDIS_DOWN_FALLBACK` / `CONFIG_NOT_FOUND_FALLBACK` の縮退ポリシー、
Pub/Sub によるキャッシュ無効化、Pub/Sub 不通時の縮退モードという
**一式の設計を Redis と一緒に引き受けている**。

rx-pixiv v1 には共有相手がいない。ダッシュボードも、ギルド別設定も、2つ目のインスタンスも無い。

一方、pixiv の作品メタデータは実質的に不変であり、キャッシュの費用対効果は極めて高い。

## Decision

**インメモリの TTL + LRU キャッシュのみを持つ。Redis も SQLite も導入しない。**

| キャッシュ | キー | TTL | 上限 |
|---|---|---|---|
| 作品メタ（illust/manga/novel） | `work:illust:{id}` | 6h | 2000 |
| ユーザープロフィール | `work:user:{id}` | 1h | 500 |
| ネガティブ（`not_found`） | `neg:{kind}:{id}` | 10min | 1000 |
| 添付 CDN URL | `att:{id}:{page}:{variant}` | min(6h, CDN の `ex` 失効時刻) | 2000 |
| 返信マップ | `reply:{originMsgId}` | 1h | 2000 |

付随する決定:

- **画像バイトをディスクにキャッシュしない**。Discord CDN が実質のキャッシュであり、
  再貼り付けは添付 URL キャッシュで拾える。計測より先に最適化しない
- `IWorkCache` は `core/ports/` に置き、**初日から非同期インターフェース**にする。
  `MemoryWorkCache` が唯一の実装だが、`RedisWorkCache` を後から差し込むときに
  シグネチャを変えなくて済む
- 統計値（閲覧数・ブックマーク数）と作品の削除は不変ではないため、TTL は有限にする

## Consequences

### Positive

- コンテナが1つで済む。docker-compose に redis サービスが要らない
- 障害モードが減る。「Redis が落ちたとき」という分岐を設計・実装・テストしなくてよい
- 依存が減り、起動が速い
- 実質不変のデータに対して、ほぼ無償でヒット率を稼げる

### Negative

- **再起動でキャッシュが飛ぶ**。起動直後は全リクエストが上流に向かう
- **返信マップが飛ぶ**ため、再起動をまたぐと元メッセージ削除に追従できず、
  Bot の返信だけが残る（rx-twitter は Redis で持つため生き残る）
- 2つ目のインスタンスを立てた瞬間に、キャッシュもレート制御も共有されなくなる

### Mitigation

- 起動直後のバーストはレート制限（[ADR 0011](0011-rate-limit-and-circuit-breaker.md)）が受け止める
- 返信マップの消失は**許容する劣化**として本 ADR に記録する。
  再起動は稀であり、残った返信は害ではない
- 2インスタンス化が必要になった時点で `RedisWorkCache` を実装する。
  そのための非同期ポートは初日から用意してある

## Rejected alternatives

### rx-twitter に倣って Redis を導入する

キャッシュのためだけに、コンテナ1つと縮退設計一式を引き受けることになる。
利用者から見た利得はゼロで、運用対象と障害モードだけが増える。
共有相手が現れた日に導入すればよい。

### SQLite で永続化する

書き込みのある永続ストアを持つと、スキーマ・マイグレーション・
バックアップという関心事が発生する。保持したいデータはすべて
「消えても致命的でないキャッシュ」であり、永続化に見合わない。

### キャッシュを持たない（rx-instagram 方式）

同じ URL が2回貼られるたびに pixiv を叩くことになる。
pixiv はレート制限が厳しく、作品メタは不変。キャッシュしない理由がない。

### 画像バイトをディスクにキャッシュする

Discord CDN が既にキャッシュとして機能しており、
添付 URL キャッシュで再貼り付けのケースは拾える。
ディスク容量管理・追い出し・破損対応という関心事を、
効果を計測する前に持ち込む理由がない。
