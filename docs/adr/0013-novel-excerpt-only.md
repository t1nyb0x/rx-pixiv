# ADR 0013: 小説は冒頭抜粋のみを展開する

- Status: Accepted
- Date: 2026-08-10
- Issue: -

## Context

pixiv の Ajax API（`/ajax/novel/{id}`）は、**本文全文**を `content` フィールドで返す。
実測でも 7000 文字を超える本文がそのまま取得できている。

小説は v1 のスコープに含まれる。しかし本文の扱いには2つの問題がある。

1. **著作権**: 本文全文を Discord に転載することは、著作物の再配信にあたる。
   画像（[ADR 0005](0005-media-delivery.md)）以上に、原著作物そのものの複製である
2. **年齢制限の抜け道**: R-18 小説は pixiv 上で一般的である。
   画像に対して年齢ゲート（[ADR 0006](0006-age-restricted-content.md)）をかけても、
   本文テキストが素通りするなら、**ゲートに穴が空いたのと同じ**である

設計レビューでは「本文を一切出さない（タイトル・作者・タグ・文字数のみ）」という
案も出た。テキスト経由の漏洩経路を完全に塞げるためである。

オーナーの判断は「**冒頭抜粋のみ**」であった。

## Decision

**本文の冒頭抜粋のみを表示する。全文は転載しない。**

表示内容:

| 項目 | 出典 |
|---|---|
| タイトル | `title` |
| 作者 | `userName` / `userId` |
| 表紙画像 | `coverUrl`（`Referer` 付き取得 → Discord 添付） |
| タグ | `tags` |
| 文字数 | `textCount` |
| **本文冒頭 300 文字**（末尾に `…`） | `content` の先頭を切り出し |
| 作品リンク | 正規 URL |

### 抜粋に対しても年齢ゲートを適用する

これが本 ADR の要である。抜粋は**画像と同じ判定表を通る**。

- 判定が `expand_plain` のとき: 抜粋をそのまま表示
- 判定が `expand_spoiler` のとき: **抜粋をスポイラー（`||...||`）で囲む**
- 判定が `link_only` のとき: **抜粋を出さない**（タイトルもタグも出さない）
- 判定が `skip` のとき: 何も投稿しない

小説にも `xRestrict` が存在する（実測で確認済み）ため、
画像作品と同じ確信度つきの年齢区分を得られる。

### 抜粋の切り出し

- HTML タグ・pixiv 独自記法（`[newpage]` 等）を除去してから切り出す
- 300 文字は文字数であり、バイト数ではない
- ルビ記法などで途中が壊れないよう、除去は保守的に行う（不明な記法は丸ごと落とす）

## Consequences

### Positive

- 引用の範囲に収まり、著作物の再配信にならない
- Embed 1枚に収まり、表示が長大にならない
- **年齢ゲートが本文にも効く**ため、テキスト経由の抜け道が塞がる
- 「続きは pixiv で」という誘導が自然に成立し、原作者の不利益にならない

### Negative

- 300 文字では作品の判断材料として不足することがある
- 抜粋の切り出しは pixiv の独自記法に依存し、記法変更で崩れうる
- R-18 小説の場合、年齢制限チャンネルでもスポイラー越しになり、読みづらい

### Mitigation

- 文字数は定数として切り出し、必要なら環境変数化できるようにしておく
- 記法の除去は保守的に行い、想定外の記法は丸ごと落とす。
  fixture ベースのテストで代表的な記法を担保する
- スポイラー越しの読みづらさは、[ADR 0006](0006-age-restricted-content.md) の
  「偽陽性は許容し偽陰性は許容しない」という非対称性の帰結として受け入れる

## Rejected alternatives

### 本文全文を分割投稿する

著作物の再配信そのものであり、採用しない。
加えて、Discord のメッセージ長制限により複数メッセージに分割することになり、
チャンネルを1作品で埋めてしまう。

### 本文を一切出さない（メタ情報のみ）

テキスト経由の漏洩経路を完全に塞げるという点では最も安全であり、
設計レビューでもこの案が推奨されていた。
ただし、小説作品において本文の手がかりが皆無だと、
展開の価値がタイトルとタグだけになり、Bot の存在意義が薄れる。

**本 ADR では、抜粋に対しても画像と同じ年齢ゲートを適用することで
漏洩経路を塞ぎ、そのうえで抜粋を出すという構成を採る。**
ゲートを通さずに抜粋を出す設計であれば、この案のほうが正しい。

### 抜粋を出すが年齢ゲートは画像にのみ適用する

**採用してはならない。** R-18 小説の本文冒頭が通常チャンネルに素通りすることになり、
[ADR 0006](0006-age-restricted-content.md) のゲートに穴が空く。
明示的に却下として記録する。
