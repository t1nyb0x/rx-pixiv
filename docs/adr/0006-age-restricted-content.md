# ADR 0006: 年齢制限コンテンツはフェイルクローズで扱う

- Status: Accepted
- Date: 2026-08-10
- Issue: -

## Context

pixiv には R-18 / R-18G 作品が一般的に流通している。
URL のプレビューを補うということは、それらを不用意に展開しうるということでもある。

**この Bot で起こしうる最悪のバグは、R-18 画像が通常チャンネルに
インライン展開されることである。** サーバー運営者にとっては規約違反であり、
Discord にとっては通報対象であり、その場に居合わせた人にとっては単に害である。

判断を難しくする事情が3つある。

1. 年齢区分の確定には作品メタデータが要る。設計時は「R-18 は無認証では取れないのでは」と
   懸念していたが、**実測により `xRestrict` は無認証で取得できると判明した**
   （[ADR 0007](0007-pixiv-session-optional.md)）。取れないのは**画像だけ**である
2. Discord のスレッドは `nsfw` 属性を**持たない**。親チャンネルから継承する必要があり、
   ここは沈黙する偽陰性（危険なのに安全と判定する）の温床になる
3. DM には年齢制限属性という概念自体が無い

オーナーの方針は「**NSFW チャンネル限定＋スポイラー**」であり、
DM は「非 NSFW 扱い」と決まっている。

## Decision

### 1. 年齢区分を確信度つきでモデル化する

```ts
type RatingLevel      = "all" | "r18" | "r18g";
type RatingConfidence = "authoritative" | "inferred" | "unknown";

interface ContentRating {
  level: RatingLevel;
  sensitive: boolean;              // xRestrict とは別軸。v1 では常に false（後述）
  ai: "no" | "yes" | "unknown";
  confidence: RatingConfidence;
}
```

**`confidence` を持たない設計では本 ADR は実装できない。**
「年齢区分が分からない」を `undefined` ではなくドメインの一級の値として扱う。

| 経路 | 判定材料 | confidence |
|---|---|---|
| Ajax | **`xRestrict`（0/1/2）**、`aiType`、タグ | `authoritative` |
| phixiv | `R-18` タグの有無 | `inferred` |
| OGP スクレイプ | 年齢確認インタースティシャルの検出 | `inferred` または `unknown` |
| いずれかが `auth_required` | **弾かれた事実そのもの** | `inferred` / level `r18` |

> **2026-08-10 の実測による更新**:
> 当初は「R-18 は無認証で取得できないので、弾かれた事実を証拠に使う」という設計だった。
> 実測の結果、**`/ajax/illust/{id}` は R-18 でも 200 を返し `xRestrict` がそのまま入っている**
> ことが分かった（[ADR 0007](0007-pixiv-session-optional.md) の実測結果）。
> したがって**年齢区分は無認証で直接・権威的に取得できる**。
> `auth_required` からの推論は、Ajax 経路が使えない場合の**予備**に降格した。
>
> 併せて、**`sl`（sanity level）は判定に使えない**ことが判明した。
> 全年齢作品でも `sl: 6` が返るため、当初の「`sl >= 4` ならセンシティブ」は誤りだった。
> **v1 では `sensitive` の判定を `sl` に基づいて行わない**（下記「センシティブの扱い」）。

`auth_required` の行は予備の経路として残す。**無認証で弾かれたという事実は、
その作品が年齢制限されていることの証拠になる。**
連鎖の後段は制限を**強める方向にしか**更新できない。

### センシティブの扱い（v1）

`sl` が使えない以上、「全年齢だがセンシティブ」を機械的に判定する手段が v1 には無い。

- **v1 では `sensitive` を常に `false` とする。** 判定表の該当行は事実上使われない
- 判定表とフィールド自体は**残す**。将来 pixiv 側に使える指標が見つかったとき、
  `NsfwPolicy` を変えずに接続できるようにしておく
- センシティブ相当の作品は `xRestrict` が付いていれば R-18 として正しく扱われる。
  付いていないものは全年齢として展開される —— これは pixiv 側の区分に従う判断であり、
  Bot 独自の推測で全年齢作品をスポイラー化するよりも予測可能である

### 2. 判定表

`NsfwPolicy.decide({ rating, channelIsNsfw, isDM })` は4つの判定のいずれかを返す。

| 年齢区分 ＼ チャンネル | 年齢制限チャンネル | 通常チャンネル |
|---|---|---|
| `all`（センシティブでない） | `expand_plain` | `expand_plain` |
| `all` かつ `sensitive` | `expand_spoiler` | `expand_spoiler`（`SENSITIVE_IN_SFW` で調整可）<br>**v1 では `sensitive` が常に false のため未使用** |
| `r18` / `r18g` | `expand_spoiler` | **`link_only`** |
| `confidence: unknown` | `link_only` | **`skip`** |

### 3. `link_only` は本当にリンクだけにする

**タイトルもタグもサムネイルも作者名も出さない。** 定型文と正規 URL のみ。
R-18 作品は題名とタグ自体が露骨なことが多く、それらを通常チャンネルに流せば
画像を止めた意味が消える。Bot 自身の返信にも `SuppressEmbeds` を立て、
Discord 側にも展開させない。

### 4. `skip` は何も投稿しない

info レベルでログに記録するだけで、チャンネルには何も出さない。

#### なぜ `link_only` は告知してよくて `skip` は駄目なのか

`link_only` は「R-18 作品のため展開しません」と**投稿する**。
一見すると、`skip` を選ぶ理由（Bot の拒否表明そのものが雑音になる）と矛盾する。
両者を分けているのは**確信度**である。

| | `link_only`（R-18 確定） | `skip`（判定不能） |
|---|---|---|
| 告知の中身 | 「これは R-18 である」— **確かな情報** | 「かもしれない」— **根拠のない嫌疑** |
| 利用者にとっての価値 | **保護的**。職場などで開かない判断材料になる | 無い。誤検知なら全年齢作品に汚名を着せる |
| 元の URL | すでに投稿者が貼っている。Bot はラベルを足すだけ | 同上 |
| 連投時 | R-18 を連投する行為自体が問題であり、可視化されてよい | 取得失敗が続くたびに雑音が積み上がる |

要するに、**確定情報のラベリングは保護であり、不確実な情報のラベリングは中傷と雑音**である。
判定不能で沈黙するのは「隠す」ためではなく、**言えることが何も無い**からである。

`UNKNOWN_RATING_SFW=link_only` で告知側に倒すこともできるが、既定は `skip` とする。

### 5. チャンネル判定

`isAgeRestricted(channel)` を1箇所に集約し、以下を扱う。

- `GuildText` / `GuildAnnouncement` / `GuildVoice` / `GuildStageVoice`: `.nsfw` を読む
- **スレッド（`PublicThread` / `PrivateThread` / `AnnouncementThread`）: `channel.parent?.nsfw` を読む**
- フォーラム投稿: フォーラムチャンネルから継承する
- **DM / グループ DM: 年齢制限チャンネルではないものとして扱う**（`ALLOW_NSFW_IN_DM` で変更可、既定 `false`）
- 未知・将来のチャンネル型: 年齢制限チャンネルではないものとして扱う

Discord の**全 `ChannelType` を網羅するテーブルテストを必須**とする。

### 6. ユーザープロフィールは作品ごとに判定する

プロフィール自体が全年齢でも、最近作に R-18 が混ざりうる。
サムネイルは**1枚ずつ**判定し、通常チャンネルで制限ありまたは判定不能なものは
そのサムネイルだけ落とす（カード全体を落とすのではない）。

## Consequences

### Positive

- **pixiv 認証がなくても年齢ゲートが完全に機能する。** `xRestrict` を無認証で
  `authoritative` に取得できるため、推論に頼る必要すらない
- 「分からない」が型に現れるので、フェイルクローズが実装漏れではなく既定動作になる
- `link_only` の内容を絞ることで、テキスト経由の漏洩も塞げる
- 判定が `NsfwPolicy` の純粋関数1つに集約され、全直積のテーブルテストで担保できる

### Negative

- **偽陽性が出る**。取得に失敗しただけの全年齢作品が、通常チャンネルで無反応になる
- 認証なしでは、年齢制限チャンネルでも R-18 の**画像**を出せない
  （メタデータは出せる）。オーナーの方針の利得が画像に関しては目減りする
- **`sensitive`（全年齢だがきわどい）を機械的に判定する手段が v1 に無い。**
  `sl` が使えないため、この軸は事実上死んでいる

### Mitigation

- 偽陽性は `pixiv_render_total{decision}` で計測する。
  `skip` の急増は年齢判定またはその上流の故障を意味するので、
  メトリクスのアラート対象にする
- 認証による改善余地は [ADR 0007](0007-pixiv-session-optional.md) に切り出した（実測済み・Accepted）
- `sensitive` の軸はフィールドと判定表を残したまま常に false とする。
  将来使える指標が見つかったとき、`NsfwPolicy` を変えずに接続できる
- `SENSITIVE_IN_SFW` を環境変数として用意し、指標が入った時点で調整できるようにする
- **偽陽性（出るべきものが出ない）は許容し、偽陰性（出てはならないものが出る）は許容しない。**
  この非対称性が本 ADR の核である

## 既知の限界

本 ADR の判定表を完全に実装しても、**塞ぎきれない穴が2つある**。設計の欠陥ではなく、
Discord と pixiv の仕様に由来する構造的な限界であり、記録しておく。

### 限界1: `Manage Messages` が無ければ、Discord 自身が R-18 タイトルを展開する

通常チャンネルに R-18 の URL が貼られたとき、**Discord のメディアプロキシが
pixiv の OGP を勝手に展開する**。これを止められるのは `message.suppressEmbeds(true)` だけで、
その権限は `Manage Messages` である（[ADR 0010](0010-suppress-not-delete.md)）。

つまり **`Manage Messages` を持たないサーバーでは、Bot がどれだけ厳格でもタイトルは漏れる。**
Bot は自分の投稿を制御できるだけで、Discord 自身の展開までは止められない。

- README では `Manage Messages` を「推奨」としているが、
  年齢ゲートの実効性の観点では**実質必須**に近い。この事実を README に明記する
- 権限が無い環境では、その旨を起動時に警告ログへ出す

### 限界2: R-18 の写像は、実データで検証できない

`NsfwPolicy` の判定表は合成データで完全にテストできる（54ケースのテーブルテスト）。
しかし**その手前** —— pixiv の実レスポンスから `ContentRating` を組み立てる写像 ——
は事情が違う。

- R-18 作品の実レスポンスを fixture としてリポジトリに置けない
- 週次のライブスモークテストも、同じ理由で R-18 を踏めない

**判定表がいくら正しくても、入口の写像が間違っていれば意味がない。**
そしてその写像だけが、継続的な検証の外側にある。

対処:

- [Plan 0005](../../.claude/addf/plans/0005-ajax-source-and-chain.md) のスパイクで**実施済み**。
  観測した構造（`xRestrict: 1` / `aiType: 2` / `/pages` が 404 / `body.urls` が null）だけを
  合成 fixture に落とす。実データの内容はリポジトリに残さない
- `xRestrict` と **`R-18` / `R-18G` タグ**の2経路で冗長に判定し、単一フィールドの誤読で倒れないようにする
  （`sl` は全年齢作品でも 6 を返すため判定に使えない）
- `pixiv_render_total{decision}` を監視する。`skip` の急増と、
  **R-18 判定の急減**の両方をアラート対象にする（後者は写像が壊れた兆候である）

## Rejected alternatives

### 判定不能なら展開する（フェイルオープン）

利便性は上がるが、「危険なものほど情報が取れない」という
本 ADR の Context の性質と正面から衝突する。
取得に失敗しやすいのはまさに R-18 作品であり、
フェイルオープンは「R-18 のときだけ規制が外れる」設計になる。

### 通常チャンネルでも常にスポイラー付きで展開する

Discord のスポイラーはクリックで誰でも解除できる。
年齢制限チャンネルという Discord 側の仕組みを迂回することになり、
サーバー運営者の意図を Bot が上書きしてしまう。

### `link_only` でタイトルとサムネイルを出す

「画像さえ出さなければよい」という発想だが、
R-18 作品はタイトルとタグ自体が露骨なことが多く、
サムネイルも pixiv 側でぼかされているとは限らない。実効性が無い。

### `skip` の代わりにエラーメッセージを投稿する

「この作品は展開できません」と出すと、
その場に「誰かが展開できないものを貼った」という情報が残る。
これ自体が漏洩であり、かつ雑音である。ログに残すだけでよい。

### スレッドの `nsfw` をそのまま読む

スレッドは `nsfw` 属性を持たない。`undefined` を falsy として扱うと
「年齢制限チャンネル内のスレッド」が通常チャンネル判定になり、
**安全側ではあるが利便性を大きく損なう**。逆に truthy 側へ倒すと危険。
親から継承するのが正しく、全 `ChannelType` のテストで担保する。
