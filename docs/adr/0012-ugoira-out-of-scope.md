# ADR 0012: うごイラを v1 スコープ外とする

- Status: Accepted
- Date: 2026-08-10
- Issue: -

## Context

pixiv の「うごイラ（ugoira）」は、フレーム画像を収めた ZIP と、
フレームごとの表示時間（delay）のメタデータで構成される。
Discord で動くものとして見せるには、これを MP4 / WebM / GIF に変換する必要があり、
**ffmpeg が要る**。

ffmpeg を Bot の本体イメージに入れると、

- イメージサイズが大きく増える
- ベースイメージの選択が縛られる（alpine では追加パッケージが要る）
- 変換は CPU とメモリを食い、Bot のメッセージ処理と同じプロセスで競合する

一方、うごイラは pixiv 上で一定の存在感があり、利用者は初日からリンクを貼ってくる。
**「対応していない」と「壊れている」は違う。** 静止した1フレームを黙って出すと、
利用者にはバグに見える。

オーナーの判断は「うごイラはロードマップ対応」である。

## Decision

**うごイラを v1 のスコープ外とする。ただし検出はする。**

- URL 種別の判定と作品メタの取得は通常どおり行う
- `illustType` が ugoira（Ajax API の `illustType === 2`）の場合、
  **静止画1枚を表示し、「うごイラ（静止画のみ表示）」と明示する**。
  無言で止まった絵を出さない
- 将来の実装に備え、メディア取得を `IMediaFetcher` ポートとして切っておく。
  返り値は `{ kind: "bytes" } | { kind: "url" }` とし、
  ffmpeg を必要とする実装を**別コンテナ（`rx-pixiv-media`）の別実装として
  差し込める**形にしておく
- **ffmpeg を本体イメージに入れない**

## Consequences

### Positive

- 本体イメージがネイティブ依存ゼロのまま保たれる
- v1 の実装範囲が絞られ、年齢ゲートという本丸に集中できる
- 利用者に「未対応」が伝わるため、バグ報告にならない
- ポートを先に切っておくことで、後から Bot 本体を触らずに追加できる

### Negative

- うごイラのリンクは v1 では静止画にしかならない。利用者の期待とのギャップが残る
- `IMediaFetcher` の抽象を、使う実装が1つしかない段階で先に作ることになる
  （やや投機的な抽象化である）

### Mitigation

- 明示ラベル（「うごイラ（静止画のみ表示）」）により、
  未対応であることを利用者に伝える
- `IMediaFetcher` の抽象は返り値の判別共用体だけに留め、
  過剰な設計をしない。2つの `kind` を持つだけの素朴なポートとする
- うごイラ URL の投稿頻度をメトリクスで観測し、
  有意になった時点で着手する（Plan「うごイラ対応」の着手トリガー）

## Rejected alternatives

### v1 で ffmpeg を本体イメージに入れて対応する

イメージサイズ、ベースイメージの制約、CPU 競合をすべて引き受けたうえで、
v1 で最も正しさが求められる年齢ゲートの実装時間を削ることになる。
優先順位が合わない。

### うごイラを検出せず、静止画として黙って出す

利用者からはバグに見える。
「動かない」より「動かないと言われる」ほうが良い。

### うごイラ URL を無視する（何も返さない）

貼った人からは Bot が壊れているように見える。
静止画とラベルを出すほうが情報量が多い。

### GIF 変換を JavaScript のみで行う

純 JS のエンコーダは存在するが、品質・速度ともに ffmpeg に大きく劣り、
フレーム delay の再現も難しい。
同じプロセスで CPU を食う問題も解決しない。
