# ADR 0007: pixiv 認証（PHPSESSID）はオプション扱いとする

- Status: **Proposed**
- Date: 2026-08-10
- Issue: -

> **この ADR はまだ決定していない。**
> 決定に必要な事実（下記「未確定の事実」）を Plan 0005 のスパイクで実測し、
> その結果を Context に追記してから Accepted / Rejected を確定する。

## Context

[ADR 0006](0006-age-restricted-content.md) の年齢ゲートは、`auth_required` 応答自体を
年齢制限の証拠として扱うことで、**認証なしでも安全側には倒れる**。
しかし「年齢制限チャンネルで R-18 を実際に見せる」には、
作品メタデータと画像 URL が必要であり、それには pixiv のログインセッションが要る可能性が高い。

一方で、`PHPSESSID` は**アカウントの完全な資格情報**である。
これを使った自動取得は pixiv の利用規約に抵触する可能性があり、
アカウント停止は現実的な帰結である。

### 未確定の事実（Plan 0005 のスパイクで実測する）

1. 無認証で R-18 作品の `/ajax/illust/{id}` を叩いたときの応答形
   （HTTP ステータス、`error` / `message` の値、メタデータだけでも返るか）
2. その応答から `auth_required`（年齢制限で弾かれた）を
   `unavailable`（単に失敗した）と**区別できるか**
3. phixiv が R-18 作品のメタデータ・画像を返すか（独自セッションを持っているか）

**分岐:**

- 区別**できる**場合 — 認証なしでも「R-18 と分かったうえで非展開」が成立する。
  PHPSESSID は「年齢制限チャンネルで実際に見せたい場合のみの追加機能」に格下げできる
- 区別**できない**場合 — フェイルクローズで安全側には倒れるが、
  年齢制限チャンネルでの R-18 展開には PHPSESSID が事実上必須になる

## Decision（案）

`PIXIV_PHPSESSID` を**任意の環境変数**として受け付ける。
**未設定でも Bot の全機能が縮退動作すること**を設計上の不変条件とする。

設定された場合の扱い:

- Cookie は **`www.pixiv.net` の ajax リクエストにのみ**付与する。
  phixiv にも `i.pximg.net` にも送らない
- 起動時に**有効性プローブ**を行い、結果をログに残す。
  以後1時間ごと、および最初の `auth_required` 発生時に再プローブする
- セッションが失効したら、警告を出して**無認証モードへ縮退**する。落とさない
- ロガーで**無条件にマスク**する（`redact: ["*.cookie", "*.PIXIV_PHPSESSID", "req.headers.cookie"]`）
- 認証時はレート制限を**より厳しく**する。
  無認証でレート制限を食うと失うのは IP だが、認証済みで目を付けられると失うのはアカウントである
- `/health` に `authenticated: boolean` を出す（値そのものは出さない）

## Consequences

### Positive

- 認証なしで全機能が動くため、リスクを取るかどうかを運用者が選べる
- Cookie の送信先を `www.pixiv.net` に限定することで、第三者サービスへの資格情報漏洩を防げる
- 失効時に縮退するので、セッション切れが障害にならない
- ログのマスクが構造的に効くため、事故的な漏洩を防げる

### Negative

- **利用規約違反とアカウント停止のリスクを運用者に負わせる**
- 未設定時、年齢制限チャンネルでも R-18 が `link_only` に留まることが多くなり、
  オーナーの方針（NSFW チャンネル限定＋スポイラー）の実効性が下がる
- セッションの手動更新という運用作業が発生する

### Mitigation

- 捨てアカウントの使用を README で明記する。本アカウントを使わせない
- 認証時のレート制限を無認証時より厳しくする
- 環境変数／シークレット経由でのみ注入する。**イメージに焼き込ませない**
- README と `.env.example` に、規約リスクを日本語で明示する

## Rejected alternatives（案）

### 認証を必須にする

無認証で v1 スコープの3種別すべてが取得できることは実測で確認済みであり、
全年齢作品のためにアカウントリスクを負わせる理由がない。

### 認証機能を実装しない

R-18 が年齢制限チャンネルでも恒久的に `link_only` になる。
オーナーの方針「NSFW チャンネル限定＋スポイラー」が実質的に空転する。
上記スパイクの結果次第では、これが正しい選択になる可能性は残る。

### refresh_token による AppAPI 認証（pixivpy 相当）

PHPSESSID より寿命が長く運用は楽になるが、
トークン取得に Selenium 相当の手順が要り、
アカウントリスクの本質（自動取得が規約に触れうる）は変わらない。
Ajax API と AppAPI の二重実装にもなる。
