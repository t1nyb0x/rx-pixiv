# rx-pixiv 要件定義

Discord に貼られた pixiv の URL を、読める形に展開する Bot。
`rx-twitter`（Twitter/X）、`rx-instagram`（Instagram）に続く3本目。

- 最終更新: 2026-08-10
- 対象バージョン: v1（初回リリース）

> **本書はこれから満たすべき要件であり、達成状況の記録ではない。**
> 実装の進捗は [TODO.md](../TODO.md) と `.claude/addf/plans/` を参照すること。

---

## 1. 背景と目的

pixiv の URL を Discord に貼っても、Discord が生成するプレビューはタイトルと pixiv のロゴ程度で、
**作品そのものが見えない**。原因は pixiv の画像 CDN `i.pximg.net` が
`Referer: https://www.pixiv.net/` を要求し、Discord の埋め込みプロキシがそのヘッダを付けられないこと。

rx-pixiv は、この欠けたプレビューを Bot 側で補う。

同時に、pixiv には Twitter/Instagram に無い固有の問題がある。**R-18 / R-18G 作品が
一般的に流通している**ことだ。プレビューを補うということは、それらを不用意に展開しうる
ということでもある。本 Bot の設計上の最優先事項は、**年齢制限コンテンツを
年齢制限チャンネル以外に出さないこと**であり、判断に迷う場面ではすべて「出さない」に倒す。

### なぜ既存の Bot を使わないのか

同種の Bot は既にある（SaucyBot / Picsiv / Embedded / FixEmbed / embed-fixer 等）。
それでも自作する理由は3つ。

1. **`rx-twitter` / `rx-instagram` と対になる自己ホスト系列であること。**
   運用・デプロイ・監視の手順を3本で揃えられる。1本だけ他人のホストに預けると、
   その1本だけ障害対応も設定変更もできなくなる
2. **年齢制限の扱いを自分で決められること。** 既存 Bot の多くは
   「NSFW チャンネルなら出す／出さない」程度の粒度で、
   **判定不能時にどちらへ倒すか**を選べない。本要件はフェイルクローズを譲れない（FR-4）
3. **削除要請に自分で応じられること。** 展開拒否リストを自分で持てる（FR-6）

逆に言えば、上記3つを要らないと判断するなら既存 Bot で十分である。

## 2. スコープ

### 2.1 v1 対象

| 種別 | URL 形 | 展開内容 |
|---|---|---|
| イラスト | `/artworks/{id}` | 画像（既定4枚）、タイトル、作者、タグ、統計、投稿日 |
| マンガ（複数ページ） | `/artworks/{id}` | 同上。全ページ数と表示枚数を明記 |
| 小説 | `/novel/show.php?id={id}` | タイトル、作者、表紙、タグ、文字数、**本文冒頭抜粋** |
| 小説シリーズ | `/novel/series/{id}` | シリーズ情報（メタのみ） |
| ユーザー | `/users/{id}` | 名前、アイコン、自己紹介、最近の作品サムネイル（最大4） |

上記に加えて解決すべき URL の異形:

- ロケール接頭辞: `/en/artworks/{id}`、`/ja/users/{id}` 等
- 旧形式: `/member_illust.php?illust_id={id}`、`/member.php?id={id}`、`/i/{id}`
- 短縮: `pixiv.me/{name}`（リダイレクト解決を経て再判定）

### 2.2 v1 スコープ外（意図的に含めない）

| 項目 | 理由 | 扱い |
|---|---|---|
| **うごイラ（ugoira）** | ZIP フレーム群 → 動画への変換に ffmpeg が必要で、本体イメージに持ち込みたくない | 検出はする。静止画1枚＋「うごイラ（静止画のみ表示）」と明示する。無言で止まった絵を出さない |
| ランキング・検索・タグ一覧 | URL 展開 Bot の役割を超える | 非対応 |
| スラッシュコマンド | v1 の設定はすべて環境変数で足りる | 非対応 |
| Web ダッシュボード・ギルド別設定 | v1 は単一インスタンスで運用し、管理面を増やさない | 非対応。Redis は永続状態に限定（[ADR 0016](adr/0016-redis-for-persistent-state.md)） |
| 原寸画像（`original`）の利用 | 帯域と権利上の露出が最大で、利用者の利得が最小 | 恒久的に非対応（[ADR 0014](adr/0014-media-delivery-via-proxy-url.md)） |
| 本文全文の転載 | 著作物の再配信にあたる | 恒久的に非対応（[ADR 0013](adr/0013-novel-excerpt-only.md)） |

## 3. 機能要件

### FR-1 URL 検出

- メッセージ本文から pixiv の URL を抽出し、種別を判定して正規化する
- 同一メッセージ内の重複 URL は1件に畳む
- **1メッセージあたり最大3 URL** まで処理する。超過分は展開せず、件数のみ注記する
- 以下は**検出しない**（偽陽性の排除）:
  - `pixivision.net` / `pixiv.help` / `sketch.pixiv.net` など別サービス
  - コードブロック（```` ``` ````）や インラインコード内の URL
  - `<https://...>` で囲まれた URL（利用者が明示的に展開を抑制している）
  - すでに `||...||` でスポイラー化されている URL

### FR-2 コンテンツ取得

- 公式 Ajax API を一次経路とし、失敗時は後続の経路へ多段フォールバックする（[ADR 0003](adr/0003-source-fallback-chain.md)）
- **HTTP 404（作品が存在しない）のときのみ連鎖を打ち切る**。他の失敗は次の経路へ進む
- 取得結果はプロセス内 LRU にキャッシュする。作品メタデータは実質不変のため
  （[ADR 0016](adr/0016-redis-for-persistent-state.md)）
- 部分的にでも取れた情報は捨てない。ページ一覧の取得に失敗しても、1ページ目だけで展開する

### FR-3 メディア配信

- `i.pximg.net` の URL を**画像プロキシの URL へホスト書き換え**して埋め込む（[ADR 0014](adr/0014-media-delivery-via-proxy-url.md)）。
  **Bot は画像バイトをダウンロードもアップロードもしない**
- プロキシの向き先は環境変数 `PXIMG_PROXY_BASE_URL`（既定 `https://phixiv.net/i`）で
  切り替えられる。自前ホストへ逃げられることが可用性の担保
- 表示枚数は既定4枚、上限10枚。総ページ数と表示枚数を「全 N ページ中 M ページを表示」と明記する
- 画像サイズは `regular`（長辺1200px）。**`original`（原寸）は使わない**
- **部分失敗の扱い**: 複数ページのうち一部の URL しか組み立てられなかった場合、
  **取れた分だけ表示し、残りは件数として注記する**。全体を諦めない
  （[ADR 0003](adr/0003-source-fallback-chain.md) の「部分成功を捨てない」と同じ方針）

### FR-4 年齢制限ゲート（最重要）

判定結果とチャンネル種別の直積で挙動を決める。

| 年齢区分 ＼ チャンネル | 年齢制限チャンネル | 通常チャンネル |
|---|---|---|
| 全年齢 | 展開 | 展開 |
| 全年齢だがセンシティブ | スポイラー付き展開 | スポイラー付き展開 |
| **R-18 / R-18G** | **スポイラー付き展開** | **`link_only`** |
| **判定不能** | `link_only` | **`skip`（無反応）** |

- `link_only`: **タイトルもタグもサムネイルも出さない**。定型文と正規 URL のみ。
  R-18 作品は題名・タグ自体が露骨なことが多く、それらを通常チャンネルへ流せば
  画像を止めた意味が無くなる
- `skip`: 何も投稿しない。「Bot が展開を拒否した」という事実自体が情報の漏洩であり、かつ雑音になる
- スレッドは**親チャンネルの年齢制限属性を継承**して判定する（スレッド自身は属性を持たない）
- **DM は年齢制限チャンネルではないものとして扱う**（全年齢のみ展開）
- 年齢区分を確定できない場合はすべて「判定不能」に倒す（フェイルクローズ）
- ユーザープロフィールの最近作サムネイルは**1枚ずつ**判定する。カード全体ではない

### FR-5 投稿の振る舞い

- 元メッセージは**削除しない**。`suppressEmbeds` で pixiv 側の貧弱なプレビューを抑制し、リプライで展開する
- `Manage Messages` 権限が無く抑制に失敗しても、展開自体は続行する
- 元メッセージが削除されたら、Bot の返信も削除する

### FR-6 管理と濫用対策

（[ADR 0015](adr/0015-admin-commands-and-abuse-control.md)）

- **オーナー専用の DM コマンド** `!owner/...` を持つ:
  `guilds` / `leave` / `ban` / `unban` / `ban-guild` / `unban-guild` / `list-bans` /
  `block` / `unblock` / `list-blocks` / `status` / `help`
- **展開拒否リスト**（削除要請の受け皿）を持つ。作品 ID 単位と pixiv ユーザー ID 単位の2粒度。
  **再デプロイなしで更新でき**、該当 URL は取得を試みずスキップする
- **クールダウン**: 利用者ごと10秒・チャンネルごと5秒。超過時は無反応（警告も出さない）
- 判定は安い順に行い、**禁止とクールダウンは URL 検出より前**に置く。
  濫用時に本文解析すら行わせない
- 禁止と展開拒否は**再起動をまたいで残る**（[ADR 0016](adr/0016-redis-for-persistent-state.md)）

## 4. 非機能要件

### NFR-1 応答性

| 指標 | 目標 |
|---|---|
| 1 URL あたりの取得総予算 | 8 秒（超過したら次の経路を起動しない） |
| 1経路あたりのタイムアウト | 3 秒（OGP 経路は 2.5 秒） |
| キャッシュヒット時 | 取得を行わず即座に描画 |

### NFR-2 上流に対する行儀

- `www.pixiv.net` へのリクエストは 1 rps 持続 / バースト 3 に制限する
- `i.pximg.net` は 8 rps / 同時4本まで
- **429 はインラインでリトライしない**。サーキットブレーカを開いて経路ごと落とす
- リトライはネットワークエラーと 5xx に対して**1回のみ**、250ms + ジッタ
- 1メッセージ内の取得同時実行は2本まで
- 画像プロキシへの負荷は、キャッシュと表示枚数上限で抑える。
  そもそも Bot は URL を貼るだけであり、実際に取得するのは Discord のメディアプロキシと閲覧者である

### NFR-3 可用性と縮退

- **どの外部依存の停止も Bot を落とさない**
- 経路ごとにサーキットブレーカを持つ（60秒内に5連続失敗で開、120秒後に半開）。
  開いている経路は待たずに即スキップする
- 経路の並びは環境変数 `SOURCE_CHAIN` で変更できる。
  死んだ経路をコード変更もリリースも無しに外せることが、この Bot で最も価値のある運用つまみ
- v1 は pixiv 認証（PHPSESSID）を受け付けない。
  **年齢判定と単ページの R-18 表示には認証を要しない**。将来、phixiv 非依存または
  R-18 複数ページ対応が必要になった場合だけ別 Plan で再判断する

### NFR-4 品質

- テストカバレッジ: 行・文・関数 **90%**、分岐 **85%**（`index.ts` と HealthServer を除く）
- 以下は網羅的なテーブルテストを必須とする:
  1. URL 検出 — 全 URL 形＋偽陽性ケース
  2. チャンネル年齢判定 — Discord の全 `ChannelType`
  3. 年齢ゲート判定 — 年齢区分 × センシティブ × 確信度 × チャンネル種別の全直積
- 外部レスポンスは zod で検証してからドメインに入れる。検証失敗は例外ではなく「経路の失敗」として扱う

### NFR-5 セキュリティ・プライバシー

- **メッセージ本文をログに出さない**。抽出した作品 ID のみ記録する
- PHPSESSID は設定として受け付けない。ロガーのマスクは誤投入への多層防御として維持する
- ヘルスエンドポイントは公開しない（Docker ネットワーク内に留める）
- Bot が要求する Discord 権限は最小限（View Channels / Send Messages / Embed Links /
  Read Message History）
- **`Manage Messages` は形式上は任意だが、年齢ゲートの実効性の観点では実質必須**。
  この権限が無いと `suppressEmbeds` できず、**Discord 自身が pixiv の OGP を展開して
  R-18 のタイトルが漏れる**（[ADR 0006 既知の限界1](adr/0006-age-restricted-content.md)）。
  権限が無い状態で起動したら警告ログを出す

> renderer差: Components V2は制限付き画像をitem単位でspoiler表示する。Embed退避経路は
> 外部画像を安全にspoiler化できないため、制限付き画像・メタデータ無しのspoilerリンクへ縮退する。

### NFR-6 可観測性

- 構造化ログ（JSON / stdout）。1メッセージ処理ごとに `traceId` を発番して追跡できること
- Prometheus 形式のメトリクスを公開する。最低限:
  経路別の取得成否、フォールバック段数、年齢ゲートの判定分布、
  メディアURL選択・書換え結果、キャッシュヒット率、サーキット状態
- `/healthz`（生存）と `/readyz`（Discord接続かつRedis connect/preload完了済みか）を分ける
- SIGTERM から5秒以内に処理中を待って正常終了する

## 5. 制約と前提

| # | 制約 |
|---|---|
| C-1 | `i.pximg.net` は `Referer: https://www.pixiv.net/` を要求する。Discord の埋め込みプロキシはこれを付けられない |
| C-2 | **R-18 作品でも `/ajax/illust/{id}` は 200 を返し `xRestrict` が取れる**（実測済み）。取得できないのは**画像だけ**で、`/ajax/illust/{id}/pages` が 404 になる。したがって年齢判定に認証は不要 |
| C-3 | 複数ページ作品は最大200ページ。Discord は 1メッセージあたり embed 10・MediaGallery item 10 |
| C-4 | `MediaGalleryItem` の `spoiler` は**外部 URL に対しても効く**（添付に限らない）。ただし v1 Embed では効かない |
| C-5 | phixiv の本家（HazelTheWitch/phixiv）は 2026-06 にアーカイブ済み。フォーク（thelaao/phixiv）が稼働中で `/api/info` と `/api/v1/statuses/` は使えない。**OGP は bot UA でのみ返る**。画像プロキシ `/i/<path>` は R-18 を含めて実バイトを返す。Rust 製・Dockerfile 同梱で自前ホスト可能 |
| C-6 | **単一インスタンス運用を前提とする。** シャーディングもマルチプロセスも想定しない |
| C-7 | 実行環境は WSL2 / Linux コンテナ |

### C-6 の再検討トリガー（スケール限界）

単一インスタンス前提は、以下のいずれかに達した時点で**破綻する**。到達前に
[Plan 0010](../.claude/addf/plans/0010-guild-config.md) を起こすこと。

| 事象 | 壊れるもの |
|---|---|
| **導入サーバーが 2500 に達する** — discord.js が自動シャーディングに入る | プロセス内キャッシュ、[ADR 0011](adr/0011-rate-limit-and-circuit-breaker.md) のプロセス内レート制御・サーキットブレーカ（シャードごとに独立してしまい、pixiv への実効レートが台数倍になる） |
| 2インスタンス目を立てる | 同上に加え、クールダウンがインスタンス間で共有されない |

現在の導入数は `!owner/guilds` と `/health` で観測できる。

### 実測で確認済みの前提（2026-08-10 時点）

| エンドポイント | 結果 |
|---|---|
| `GET /ajax/illust/{id}` | 無認証で `{error:false, body:{...}}`。メタデータは返るが `body.urls` は全て null |
| `GET /ajax/illust/{id}/pages` | `body` は配列。要素は `urls{thumb_mini,small,regular,original}` + `width`/`height`。**画像 URL はここからしか取れない**（`/ajax/illust/{id}` の `body.urls` は全年齢作品でも常に null） |
| 同上（R-18 作品） | **HTTP 404**・`error:true`・`body:[]`。作品は実在するので `not_found` に写像してはならない |
| `GET /ajax/illust/{id}`（R-18） | HTTP 200・`error:false`・**`xRestrict:1`**・`aiType:2` |
| `sl`（sanity level） | **全年齢作品でも 6**。センシティブ判定には使えない |
| phixiv `/artworks/{id}`（**bot UA 必須**） | 通常の UA では 307 で pixiv へ転送される。bot UA なら OGP を返し、**R-18 でも `og:image` がある**。画像 URL は `https://phixiv.net/i/...` で UA を問わず実バイトを返す |
| phixiv `/api/v1/statuses/{id}` | **要求した ID と異なる作品を返す**。使用しない |
| `GET /ajax/novel/{id}` | 無認証で `content`（本文全文）・`coverUrl`・`xRestrict`・`tags` を返す |
| `GET /ajax/user/{id}?full=1` | 無認証で `name`/`imageBig`/`comment`/`webpage`/`social` を返す |
| `GET /ajax/illust/1`（存在しない） | HTTP 404 |
| `https://phixiv.net/artworks/{id}` | 稼働中。作品タイトルを解決できた |

v1 の全対象（作品・小説・小説シリーズ・ユーザー）が**無認証の公式 Ajax API で賄える**。
小説シリーズは `GET /ajax/novel/series/{id}` を実測し、実装済み。
